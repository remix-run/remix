# Dialog implementation plan

**Goal:** Add a headless dialog to `@remix-run/ui`, using Base UI v1.9.0 as a behavioral reference and Remix's provider/mixin conventions.

**Architecture:** `dialog.Context` owns controlled or uncontrolled open state. `dialog.surface()` adapts an app-owned element. Explicit focus scopes manage modality and focus containment, while a shared dismissal stack coordinates dialogs and existing popovers. Manual popovers provide visual top-layer placement only. Role mixins register triggers, labels, descriptions, close buttons, focus targets, and an optional custom backdrop. Reuse the existing scroll-lock utility and keep styles consumer-owned.

**Constraints:** No React or Floating UI dependency. Use named exports, type aliases, stable context getters, component lifetime state, queued DOM work, abort cleanup, and bubbling public events. No commits or pushes without a user request.

Usage:

```tsx
import * as dialog from '@remix-run/ui/dialog'

function ProfileDialog() {
  return () => (
    <dialog.Context>
      <button mix={dialog.trigger()}>Edit profile</button>
      <div mix={dialog.backdrop()} />
      <section mix={dialog.surface()}>
        <h2 mix={dialog.title()}>Edit profile</h2>
        <p mix={dialog.description()}>Update your public details.</p>
        <input aria-label="Display name" mix={dialog.focusOnShow()} />
        <button mix={dialog.close()}>Done</button>
      </section>
    </dialog.Context>
  )
}
```

The user requires custom markup and consistent interaction behavior across browsers. Modal, non-modal, and focus-trap-only modes share explicit focus management. Imperative refs support external triggers; payload state remains app-owned. Top-layer rendering avoids relocating DOM nodes. Validate Chromium, Firefox, and WebKit without claiming physical mobile Safari parity.

## Ordinary DOM overlays and portals

The user explicitly authorized removing mandatory native top-layer placement. This supersedes the earlier deferral above. Dialogs and the shared popover used by menu, select, and combobox render ordinary elements. An explicit `Portal` from `@remix-run/ui/portal` creates a Remix-owned root in the document body or a specified container, preserving context and frame. Inline placement remains available. Shared dismissal ownership also assigns visual stacking order, with a backdrop immediately below its dialog. CSS uses `data-open` for mounted visibility and `data-state` for requested state; closed transition content remains visible until completion. Consumers may integrate other ordinary DOM layers with z-index, but unrelated widgets still need to respect modal focus/inert boundaries.
