BREAKING CHANGE: Replace `createAssetServer({ fingerprint: { buildId } })` with `createAssetServer({ fingerprint: true })`. Scripts now keep JavaScript imports as authored and rely on import maps for browser resolution. Fingerprinted assets use hashes of their final emitted bytes instead of per-build source hashes, and the same import maps resolve stable asset URLs to the current fingerprinted URLs. Call `assetServer.getScriptEntry()` for each rendered script entry and include its returned import map before its modulepreload links and module script. In development, HMR installs any new import map entries required by an accepted module graph before evaluating the update and reloads the page if an installed mapping would need to change. Assets browser updates are stored under their versioned namespace as `{ timestamp, updates }` rather than a nested `{ type: 'browser:update', timestamp, updates }` payload.

If you previously relied on `fingerprint.buildId` to namespace persisted transformed file cache entries, move that value to `files.cacheKey`. For example, use `files: { cache, cacheKey: process.env.GIT_COMMIT_SHA }` in production to reuse transformed file outputs across server restarts for the same build. When `files.cacheKey` is omitted, transformed file caches use a random per-process namespace.
