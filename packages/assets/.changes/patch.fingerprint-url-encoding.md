Fingerprinted asset URLs now use a `.~<fingerprint>` segment instead of `.@<fingerprint>`, for example `/assets/app/styles.~k3x9f2.css`. If you have CDN, cache, service worker, or `_headers` rules that match `.@` in asset paths, update them to match `.~`.

This fixes fingerprinted assets on Cloudflare Workers Static Assets. Hosts that canonicalize each path segment with `encodeURIComponent`, including Cloudflare's asset router, answered every `.@` URL with a `307` redirect to its `%40` form, adding a round trip per asset and skipping `_headers` rules written for the original path. The new URLs are already canonical, so these hosts serve them directly.

The asset server still serves `.@<fingerprint>` requests, so pages cached from earlier deployments keep loading assets whose content hasn't changed. Assets whose emitted content changes with the new URL format, such as stylesheets that reference other assets and scripts with external source maps, get new fingerprints, so their old URLs no longer resolve. The asset server also matches percent-encoded fingerprint separators such as `styles.%40k3x9f2.css`, and request paths with malformed percent-encoding or null bytes now return `null` instead of throwing.
