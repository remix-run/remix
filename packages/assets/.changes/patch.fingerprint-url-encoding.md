Serve fingerprinted assets on Cloudflare Workers Static Assets without a redirect. Fingerprinted URLs now use a `.~<fingerprint>` segment, such as `/assets/app/styles.~k3x9f2.css`, instead of `.@<fingerprint>`. Hosts that canonicalize each path segment with `encodeURIComponent`, including Cloudflare's asset router, previously answered every `.@` URL with a `307` redirect to its `%40` form, adding a round trip per asset and skipping `_headers` rules written for the original path. The new URLs are already canonical, so these hosts serve them directly.

The asset server still serves the `.@<fingerprint>` form, so cached pages and HTML from earlier deployments keep working. It also decodes request path segments before matching fingerprints, so percent-encoded requests such as `/assets/app/styles.%40k3x9f2.css` are served instead of returning `null`. Requests with malformed percent-encoding now return `null` instead of throwing. If you have CDN, cache, or `_headers` rules that match `.@` in asset paths, update them to match `.~`.
