BREAKING CHANGE: Requests that match one or more route patterns, but no route registered for the request method, now receive a `405 Method Not Allowed` response with an `Allow` header listing the methods registered for that URL. Previously these requests fell through to the router's `defaultHandler` and produced a `404 Not Found` by default. Matching still falls through to less specific routes that can handle the method (including `ANY` routes) before the 405 applies, so catch-all routes keep handling these requests. Use the new `methodNotAllowedHandler` option in `createRouter()` to customize the response, or register an `ANY` route if you want a handler to receive every method at a given URL.
