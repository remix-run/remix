Fix `context.render()` responding with `200` when a component throws while rendering the shell, which left servers unable to send a `500` and reset the connection after the headers were sent. The `render()` middleware now waits for the first chunk of HTML before returning the response, so shell render errors reject `router.fetch()` like any other action error and reach the server's error handling, such as the `onError` option of `createRequestListener()`. Errors in non-blocking frame content streamed after the shell are still reported to `onError` without changing the response status.
