`Accept`, `AcceptLanguage`, and `AcceptEncoding` now use the most specific matching range when computing `getWeight()`, `accepts()`, and `getPreferred()`, as required by RFC 9110. Previously the highest-weighted matching range won, so a header like `text/html;q=0, */*` still reported `text/html` as acceptable with a weight of `1`. Now an exact media type beats `type/*`, which beats `*/*`; a language range like `en-US` beats `en`, which beats `*`; and an explicitly listed encoding beats `*`.
