`Vary` now keeps each header name as it was first given instead of lowercasing it, so `new Vary(['Cookie', 'Accept-Encoding']).toString()` returns `'Cookie, Accept-Encoding'` and responses keep the spelling your app wrote, including after compression adds `Accept-Encoding`. `has()`, `add()` and `delete()` still compare names case-insensitively, and a repeated name keeps its first spelling. Some caches, notably WebKit's (Safari), only vary on cookies when the `Vary` name is spelled exactly `Cookie`, so a lowercased `Vary: cookie` could let a private, personalized response be reused for a different session in the same browser.
