Server rendering with `remix/component` is about twice as fast as in 3.0 and uses less memory, with no code changes. Rendering a 48-product listing page with `renderToString()` takes 244 µs instead of 513 µs (Node.js 24.18 on an Apple M5 Pro, median of 5 fresh-process runs, identical HTML output). Under sustained HTTP load on a 24-product store page, assembling each response with a single join lowers the server's resident memory after load from 793 MiB to 527 MiB (see #12006, #12016, #12018, and #12020).

Apps that render client entries also benefit from `getScriptEntry()` caching in `remix/assets`: a warm lookup takes about 3 µs instead of 210 µs (see #12005). See the [`@remix-run/component`](https://github.com/remix-run/remix/blob/main/packages/component/CHANGELOG.md) and [`@remix-run/assets`](https://github.com/remix-run/remix/blob/main/packages/assets/CHANGELOG.md) changelogs for details.
