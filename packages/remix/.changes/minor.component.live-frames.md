Keep a `<Frame>` from `remix/component` up to date over one connection by pointing its `src` at a route that answers with `Content-Type: text/event-stream`. Events named `rmx-append` and `rmx-replace` carry frame HTML: one adds to what the frame shows, the other replaces it, reconciled the way reload HTML is, and events with any other name are left for whatever else reads the stream. The frame resolves as soon as the first event renders, frames reading the same source share one connection, a dropped connection is resumed with `Last-Event-Id`, and each rendered event dispatches a bubbling `rmx:update` for the UI around the frame to react to.
