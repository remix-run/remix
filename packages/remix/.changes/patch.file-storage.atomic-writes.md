The filesystem backend at `remix/file-storage/fs` preserves previous entries when uploads fail during staging, using the same API and disk format without an opt-in or migration. Publication uses two renames; failure between them can leave complete new content with old metadata, or an unpublished new entry. Replacements require create, rename, and remove permissions in storage subdirectories and preserve POSIX read/write/execute mode bits, while ownership and ACLs follow the filesystem's rules for new files. See the [filesystem storage documentation](https://github.com/remix-run/remix/tree/main/packages/file-storage#replacement-writes) for retry, rollback, and filesystem requirements.
