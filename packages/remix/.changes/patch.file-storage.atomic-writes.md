The filesystem backend at `remix/file-storage/fs` preserves previous entries when uploads fail during staging, using the same API and disk format without an opt-in or migration. Publication uses two renames; failure between them can leave complete new content with old metadata, or an unpublished new entry. Storage directories are managed by the application with consistent filesystem permissions across deployments; replacements preserve POSIX read/write/execute mode bits but do not copy custom per-file ownership or ACLs. See the [filesystem storage documentation](https://github.com/remix-run/remix/tree/main/packages/file-storage#replacement-writes) for retry, rollback, and filesystem requirements.
