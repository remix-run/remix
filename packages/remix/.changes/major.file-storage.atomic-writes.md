The filesystem backend at `remix/file-storage/fs` now requires create, rename, and remove permissions in storage subdirectories. Replacements preserve POSIX read/write/execute mode bits but use the filesystem's ownership and ACL rules for new files. Upload failures during staging preserve the previous entry, using the same API and disk format without an opt-in or migration. Publication uses two renames; failure between them can leave complete new content with old metadata, or an unpublished new entry. See the [filesystem storage documentation](https://github.com/remix-run/remix/tree/main/packages/file-storage#replacement-writes) for retry, rollback, and filesystem requirements.
