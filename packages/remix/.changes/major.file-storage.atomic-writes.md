Filesystem storage preserves previous entries when uploads fail during staging, using the existing `remix/file-storage/fs` API and storage format. Replacements require create/rename/remove permissions in storage subdirectories, preserve POSIX mode bits, and use the filesystem's ownership and ACL rules for new files. Publication uses two renames: failure between them can leave complete new content with old metadata, or an unpublished new entry. See the [filesystem storage documentation](https://github.com/remix-run/remix/tree/main/packages/file-storage#replacement-writes) for failure and filesystem requirements.
