`remix/router` now treats `request.signal` cooperatively. When a request aborts, the router stops running middleware and handlers and rejects with the abort reason, but it waits for work already in progress instead of rejecting immediately. Pass `context.request.signal` to work that should stop when the client disconnects, such as `fetch()` calls and database queries. See the [`@remix-run/fetch-router` changelog](https://github.com/remix-run/remix/blob/main/packages/fetch-router/CHANGELOG.md) for details.
