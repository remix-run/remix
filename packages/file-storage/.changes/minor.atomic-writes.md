BREAKING CHANGE: Filesystem storage now writes versioned content files and atomically replaces metadata, preserving the previous entry when a write fails (see #11909). Existing entries remain readable and can still be removed or replaced if their content is missing. Older package versions cannot read rewritten entries; upgrade all processes sharing a storage directory together. Callers must coordinate overlapping operations, including consumption of returned lazy files. Cleanup is best-effort and power-loss durability is not guaranteed.
