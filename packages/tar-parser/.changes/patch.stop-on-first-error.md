Stop reading the archive at the first handler rejection, and cancel a `ReadableStream` archive whenever `parseTar()` stops early. Before, an `async` handler's rejection was only reported after the rest of the archive was read, and was lost if parsing then failed, for example with `MaxTotalSizeExceededError` once a large archive passed `maxTotalSize`. Handlers kept being called for later entries in the meantime. A stream archive was also left locked and never cancelled after a limit error, invalid archive, or handler error, so a source like a `fetch()` response stayed open. Now `parseTar()` rejects with the handler's error as soon as it is observed, handlers aren't called for later entries of a stream or async iterable archive, and a `ReadableStream` archive is cancelled with the error.
