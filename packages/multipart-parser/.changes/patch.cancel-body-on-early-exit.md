Cancel the input stream when `parseMultipartStream()` or `parseMultipartRequest()` stops reading before the stream ends, because a limit like `maxTotalSize` was exceeded, the message was malformed, or the caller stopped iterating. The error, if there is one, is the cancel reason. Before, the stream was abandoned instead, so its source never learned it could stop. For example, an upstream `fetch()` response stayed open after a limit error. With the `remix/multipart-parser/node` entrypoint, the Node.js stream is now destroyed in this case, so an `http.IncomingMessage` emits `'aborted'` and `'close'`, and passes the error to any `'error'` listeners. Its `socket` property is `null` afterwards, so read anything you need from `req.socket`, such as the client address, before parsing.
