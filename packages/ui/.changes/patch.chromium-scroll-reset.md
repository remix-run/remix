Fix two Chromium scroll bugs on push and replace navigations. Chrome 148 and earlier ignore the Navigation API scroll reset for destinations without a fragment (see [crbug 479874917](https://crbug.com/479874917)), so navigating from a scrolled position left the page scrolled; Remix now scrolls to the top when the browser skips the reset. Chromium also retries scroll restoration for a reloaded or history-loaded document once it finishes loading, so navigating before `load` completes jumped to the previous page's saved position; Remix now opts the new entry out of restoration until that retry has run.
