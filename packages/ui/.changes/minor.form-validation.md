Use one form schema from `remix/data-schema/form` for submission parsing and native controls (see #11630). `form.Context` supplies stable typed field bindings that pass through ordinary component props; `root`, `control`, `label`, and `error` mixins provide constraints, validity, and accessible associations while applications own markup.

Context consumes failed `fd.parseSafe(schema, data)` results directly from `remix/data-schema/form`, which owns restoration, grouped messages, and sensitive-field/file omission. Single selects restore submitted selections through server rendering and hydration, and refresh their native reset defaults on new submissions. Sensitive controls clear on failed submissions while ordinary rerenders preserve live edits. The render prop always supplies `errors`, with `errors.form` absent when there are no form-level messages. Live errors appear after blur or blocked submission; server errors appear immediately. Shared field error maps, supplemental `setCustomErrors()`, native reset, and new submissions update feedback without setup factories or subscriptions.

Text bindings support native string inputs, including date/time, color, hidden, and radio controls, as well as select and textarea. Radio options share feedback and restore selected defaults; use `label(field, value)` for each option's scoped label. Numeric bindings support range inputs. File and file-list bindings validate selected uploads and clear selections on failed submissions. Constraints follow native control capabilities, with date/time bounds authored in markup and action inputs retaining native behavior.
