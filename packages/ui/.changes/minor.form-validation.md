Native controls can share schema-backed validation, SSR constraints, restored values, and accessible error linkage without giving up application-owned markup. Use `createFieldMixins(fieldDefinition, { name, getSubmission, onChange })` for one input, select, or textarea, or `createFormMixins(formDefinition, { getSubmission, onChange })` for a form. Both use the same field behavior; independent fields can compose into an ordinary native form.

Form bindings expose `form`, `field`, `label`, and `error` mixin factories and live read-only `fields.name.errors` and `touched` state. Standalone bindings expose the state directly. `input(name)` and `errors.name` remain available on form bindings. `onChange` requests rendering when errors or touched state change. New server submissions and non-canceled native resets reset touched state. Native constraints remain primary, server errors stay visible until editing, and `label()` and `error()` supply only label association and the error-element id, including during SSR. `onInputValidation()` exposes snapshots of messages and touched state for lower-level observation. The standalone `form()` mixin enhances unmanaged native controls. Import these APIs from `@remix-run/ui/form` and provide control styles in the application.

Supplement native/schema checks with client-only `validations`, including async availability checks. Typing is debounced (300ms by default, configurable per field) and blur checks immediately. Superseded checks are aborted and stale results ignored. Live `pending` and `validationError` state distinguishes outstanding or failed checks from invalid values. Pending checks do not delay submission; completed errors use native submission blocking. Server handlers remain responsible for authoritative business validation (see #11630).
