`staticFiles()` now serves files whose names contain spaces, reserved characters, or non-ASCII characters. Request paths are percent-decoded one segment at a time before they are resolved, so `/my%20file.txt` serves `my file.txt` and `/caf%C3%A9.txt` serves `café.txt`; previously these requests looked for the literal encoded name and fell through. The `filter` option receives the decoded path. Requests with malformed escapes, or with segments that decode to `/`, `\`, a null byte, `.`, or `..`, fall through to the next handler. Directory listings now encode entry names in links and show the decoded directory path in the title.
