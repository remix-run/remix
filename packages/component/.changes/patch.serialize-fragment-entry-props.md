Fix `clientEntry` props that contain JSX fragments, including components that render fragments, so their content is no longer serialized as `null` and dropped once the entry re-renders on the client (see #12065). String and number `key`s on elements and fragments in `clientEntry` props are now preserved too, so reordering keyed content after hydration moves the existing DOM nodes instead of patching them in place. Other key types still can't round-trip through JSON, so they are omitted and those elements fall back to matching by position.
