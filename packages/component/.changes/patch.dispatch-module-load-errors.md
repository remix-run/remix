Fix `error` listeners on the `run()` runtime missing client entries that fail to load. When `loadModule` throws, rejects, or returns something other than a function, during initial hydration or after a frame navigation or reload, the runtime now dispatches an `error` event carrying that error, the same way it reports component render and frame resolution errors, so error overlays and reporting code see the failure instead of only a `console.error` message. Client entries that use the same component share one load, so each failed load dispatches one event. The entry keeps its server-rendered HTML as before. Roots created with `createRoot()` or `createRangeRoot()` dispatch the same event for client entries inside a `<Frame>`.
