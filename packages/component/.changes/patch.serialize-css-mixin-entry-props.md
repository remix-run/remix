Fix hydration of `clientEntry` components whose props contain JSX elements styled with `css()`. Hydration used to fail with `Framework invariant: Invalid mix prop`, and the client entry never became interactive. `css()` mixins in client entry props, including arrays like `mix={[css(base), css(active)]}`, now reach the browser with their styles, and content from those props that the server didn't render is styled when the client entry renders it later. Styles with `undefined` properties keep the same generated classes and cascade order through hydration.

Other mixins, such as `on()`, `ref()`, and custom mixins from `createMixin()`, are not supported in serialized client entry props. When a client entry renders an element from its props that uses one, it now reports an error explaining that only `css()` mixins can be serialized and that those elements should be rendered inside the client entry instead, rather than failing with `Invalid mix prop`.
