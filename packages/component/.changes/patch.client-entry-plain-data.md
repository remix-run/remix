Fix plain data in `clientEntry` props being treated as JSX elements, frames, fragments, or `css()` mixins during hydration when it contains keys Remix uses for serialization, such as `$rmx` or `$rmxMixin`. These objects now reach the client entry unchanged at any nesting level, including the top-level props object. Own `__proto__` properties are kept as data instead of changing the object's prototype.

Only elements created with JSX or `createElement()` now render. Objects built by hand or parsed from JSON with the same shape as an element, such as `{ $rmx: true, type: 'div', props: { innerHTML } }`, are no longer rendered as elements and throw `Invalid child node` when passed as children. This keeps data from a database or API from injecting markup. Spread copies of elements, such as `{ ...element }`, still render.
