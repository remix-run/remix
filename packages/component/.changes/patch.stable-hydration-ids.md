Make `handle.id` for components and mixins below a client entry stay the same when the entry hydrates. IDs are now derived from the entry's server-rendered id and the render order within it, so `aria-controls`, `for`, and similar references to server-rendered markup keep working after hydration. Previously the server rendered `s<random>-<n>` and `ssr-mixin` while the client reassigned `c<n>` and `m<n>`.
