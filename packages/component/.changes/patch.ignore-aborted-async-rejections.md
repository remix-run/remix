Async `on()` handlers and `queueTask()` callbacks no longer produce unhandled promise rejections after the runtime aborts the signal passed to their work. This includes requests aborted when an event handler runs again, a component renders again, or its element is removed. Rejections while the signal is live still surface as unhandled promise rejections, including failures from returned thenables. Component tasks that omit the signal parameter retain their existing rejection behavior when no task in the same commit requests a signal, including the internal task queued by `handle.update()`. Pending tasks flushed on component removal receive an aborted cancellation signal even if they omit the parameter.
