Open links that point at a file instead of rendering the file into the page. After `run()` starts the runtime, clicking a link to an image, a PDF, or another non-HTML URL changed the address bar and showed the response's bytes as text, because the Navigation API commits the destination before Remix fetches it. Opting out was only possible on the link itself, with `data-rmx-document`, `download`, or a `target`, which links written in Markdown or CMS content can't carry.

A GET navigation to the current document whose response declares a content type other than `text/html`, `application/xhtml+xml`, or `text/plain` now discards the body and loads the destination as its own document, so the browser opens the file as it would without the runtime. This costs a second request for the file, usually served from the browser's cache; `data-rmx-document` still skips the first request for a link you already know points at a file.

Responses typed `text/plain` keep rendering into the page, because the `Response` constructor applies that type to every string body and a `resolveFrame` that returns `new Response(html)` must keep working. Responses with no content type, non-GET submissions, and responses aimed at a named frame are unchanged as well. Use `data-rmx-document` for links to plain-text endpoints.
