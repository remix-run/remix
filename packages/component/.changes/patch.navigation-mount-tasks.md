Run `handle.queueTask()` tasks from components rendered during a frame navigation after the navigation finishes, once scroll and focus are reset or restored (see #12001). If another navigation interrupts it, the tasks wait for that navigation as well, so components it removed see an aborted signal. Previously, these tasks ran in the middle of the navigation, before or after the scroll reset depending on whether the component's module was already loaded. A client entry that replaced the URL from a mount task, such as `navigate(href, { history: 'replace', resetScroll: false })`, could cancel the scroll reset and leave the page at the previous page's scroll position.
