Server rendering is about twice as fast and uses less memory, with unchanged HTML output. Rendering a 48-product listing page with `renderToString()` takes 244 µs instead of 513 µs compared to `@remix-run/component` 1.0.0 (Node.js 24.18 on an Apple M5 Pro, median of 5 fresh-process runs). Under sustained HTTP load on a 24-product store page, assembling each response with a single join lowers the server's resident memory after load from 793 MiB to 527 MiB (see #12016, #12018, and #12020).

The renderer no longer creates a promise per static node, skips setup for browser-only mixins such as `on()`, and inserts head resources and hydration data in a single pass. Blocking frames still resolve before the first HTML chunk. Request abort listeners are now removed when rendering finishes, fails, or is canceled, so long-lived request signals no longer keep finished renders reachable.
