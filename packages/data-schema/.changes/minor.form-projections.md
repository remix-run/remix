Added `getConstraints()` to derive native HTML requiredness, numeric step, and length/range attributes from a schema and input type.

Added `createForm({ schema?, fields })` in `@remix-run/data-schema/form` to project selected object-schema fields into native text, number, and checkbox attributes, add schema-backed ancillary fields, and decode submitted `FormData` with serializable raw values and field/form errors on failure. Omit the backing `schema` when every field supplies its own inline schema. Resolved fields expose schema-derived requiredness for rendering labels and indicators. Failed results can be passed back to `getInputAttrs()` to restore non-password values and connect accessible server errors. `createInputValidator()` reuses a projected field's schema and form-value decoder to set synchronous schema issues through the native Constraint Validation API.

Define reusable fields with `createField({ schema, label, type })`, parse them independently with `Field.parse(formData, name)`, or compose them into `createForm({ fields })`. Form definitions expose resolved field definitions through `Form.fields`, using the same constraint derivation and validation as standalone fields.

Customize field messages once with `errorMap` on a reusable field or a form field entry. Parsing and input validation use the same map, including `value.required` for missing required values. Explicit check and refinement messages are overridable defaults; custom checks without a code use `check.failed`. Returning `undefined` preserves the default message.
