Validate native form submissions with `remix/data-schema/form` (see #11630). `object`, `text`, `password`, `number`, and `checkbox` describe form decoding while reusing ordinary scalar schemas, checks, and transforms. The functional `fd.parse(schema, data)` and `fd.parseSafe(schema, data)` APIs follow ordinary schema parsing conventions. Safe parsing preserves success/value/issues and extends failures with raw restorable values and grouped errors, omitting sensitive fields, files, and arbitrary issue metadata. Scalar fields can opt in with `{ sensitive: true }`; passwords are always sensitive. Successful parsing still returns validated sensitive values. Only fields with messages appear in `errors.fields`; `errors.form` is absent without form-level messages. Core `s.parseSafe` keeps its existing contract. Readonly entries expose original schemas and form kinds to UI adapters. Missing and blank text/number entries reach the supplied schema as `undefined` by default; text and password fields can preserve empty strings explicitly. Checkboxes decode by presence. The existing `form-data` export retains its extraction semantics.

FormData object parsing also retains reserved logical keys such as `__proto__` as ordinary own properties.

String-valued native controls, including date/time, color, hidden, and radio groups, use `text`; range inputs use `number`. File entries normalize the browser's unnamed zero-byte upload placeholder to `undefined` or an empty file list while preserving named zero-byte files. The lower-level `form-data` adapter keeps its existing extraction behavior.
